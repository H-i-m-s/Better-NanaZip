# NanaZip 定制版 · 构建流程与注意事项

> 供其他会话/模型参考。仓库位置：`E:\NanaZip`（git 工作区）。
> 本文件随仓库管理（`build\` 进 git），克隆后即可按此构建。
> `.local\` 被 .gitignore 忽略（解包运行目录/本地产物，不进 git，可随时删）。
> 包身份：`SSS.NanaZip.RemotePassword`，Publisher `CN=SSS NanaZip Development`，证书工具链见 `build\SSSDevSigning\README.md`。
> 当前迭代基线：包版本 6.5.1825.0。

## 一、统一构建入口（推荐，日常一律用它）

总文件 `build\构建发布.ps1` + 子文件 `build\步骤\`（01 编译 / 02 打包 msix / 03 组装文件集 / 04 编译 exe / 05 汇总发布），一条命令出全部产物。

```powershell
# 日常开发：编译 + 替换 pkg91（最快，秒~分钟级）
& 'E:\NanaZip\build\构建发布.ps1' -Mode 替换

# 出安装包：增量编译 → msix → 签名（3~5 分钟）
& 'E:\NanaZip\build\构建发布.ps1' -Mode 构建 -Format msix -Version 6.5.1826.0

# 不编译，用现有 bundle 直接组装 exe/绿色版（<1 分钟）
& 'E:\NanaZip\build\构建发布.ps1' -Mode 打包 -Format all

# 全量：清构建缓存重建 + 全格式（~25 分钟，需 -Force 确认）
& 'E:\NanaZip\build\构建发布.ps1' -Mode 全量 -Version 6.5.1826.0 -Arch both
```

参数：

| 参数 | 可选值 | 默认 | 说明 |
|---|---|---|---|
| `-Mode` | 替换 / 构建 / 打包 / 全量 | 构建 | 替换=编译+替换 pkg91；构建=增量编译+打包；打包=用现有产物；全量=清缓存重编 |
| `-Format` | msix / exe / green / all | all | 输出格式（替换模式忽略） |
| `-Arch` | x64 / both | x64 | both = x64+arm64 bundle |
| `-Version` | 如 6.5.1826.0 | manifest 现值 | 自动写入 manifest |
| `-Sign` | 开关 | 开 | `-Sign:$false` 跳过签名 |
| `-SkipPri` | 开关 | 关 | 纯 .cpp 改动时跳过 resources.pri |
| `-Force` | 开关 | 关 | 全量模式跳过确认 |

产物统一在 `Output\发布\<版本>\`：msixbundle / setup.exe（含 FM + Win11 右键菜单壳包）/ 绿色版.zip / .cer / 安装说明.txt。
**全量模式只清 `Output\Objects + Output\Binaries`（构建缓存），不会动发布目录。**

注意：脚本文件必须保持 **UTF-8 BOM** 编码（PowerShell 5.1 中文解析依赖 BOM，无 BOM 按 GBK 读会语法错乱）。

## 二、模式详解

### 替换（= 原 `更新pkg91.ps1`）
1. 杀 NanaZip 进程（解锁 DLL）。
2. 单入口编译 FM（依赖图自动展开全项目，见下"编译命令"）。
3. 默认 wapproj x64 单平台打包刷新 `resources.pri`（`-SkipPri` 跳过，规则见第四节）。
4. 18 文件白名单替换到 `pkg91\x64`（按时间戳，源取 `Output\Binaries\Release\x64` 与 `...\NanaZipPackage\x64` 最新者；缺失从 `pkg90\x64` 补齐）。
5. 布局核对（对照 pkg90，pkg90 缺失自动跳过）。

### 构建（= 原 `打包x64.ps1`）
`01-编译` 增量 → `02-打包msix`（wapproj bundle + 签名）→ 按 Format 走 03/04/05。

### 打包
跳过编译，用现有最新 bundle 直接组装 exe / 绿色版（版本从 bundle 文件名解析）。

### 全量
确认（`-Force` 跳过）→ 清 `Output\Objects + Output\Binaries` → 全链重编 → 同构建。

更彻底的干净发布（清整个 Output + Debug + Release 全编）仍可用 `build\SSSDevSigning\Build-SSSNanaZipPackage.ps1 -SignAllMsix`（~21 分钟）。

## 三、编译命令与要点（手动编译的唯一正确入口）

```
cmd /c "call "C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat" >nul 2>&1 && msbuild NanaZip.UI.Modern\NanaZip.Modern.FileManager.vcxproj /p:Configuration=Release /p:Platform=x64 /m /v:minimal /nologo"
```

要点（每条都实测过）：
- **只编 `NanaZip.Modern.FileManager.vcxproj` 一个项目**。vcxproj 层通过 props 全局注入依赖，MSBuild 自动展开整个依赖图（K7Base / K7User / Codecs / Core / Modern / ShellExtension / Universal.Windows + 各 Sfx），一次编全。实测比"11 项目循环"快 5 倍（264s → 48s）。唯一例外：`Universal.Console` 不在 FM 依赖链上，改它才需单独编。
- **vcvars64.bat**（原生 x64 环境），不要用 vcvarsall x86。
- **/m** 全核并行，**/v:minimal /nologo** 精简输出。
- 不要用 slnx / wapproj 做"只编译"：slnx 会打包+编 ARM64，wapproj 的 Build 把编译与打包焊死。
- 产物：`E:\NanaZip\Output\Binaries\Release\x64\`。
- arm64 由 wapproj 打包时自动交叉编译（`-Arch both` → `AppxBundlePlatforms=x64|arm64`）。

## 四、resources.pri 判断规则

| 改动类型 | 是否需要刷新 pri |
|---|---|
| `*.xaml` / `App.xaml` / `*.resw` / Manifest | **需要**（不带 `-SkipPri`） |
| 只改 `*.cpp` / `*.h`（纯逻辑） | **不需要**（加 `-SkipPri`） |

## 五、版本号机制

- 每次装包验证前必须升版本：Windows 不允许同版本不同内容覆盖安装（0x80073CFB，`ForceUpdateFromAnyVersion` 只管版本比较不管内容 hash）。
- 用 `-Version` 传入（自动写入 `NanaZipPackage\Package.appxmanifest`），或全量构建时由 RefreshVersion 按 git 提交日期自动算（`NanaZip.Project\NanaZip.Project.Version.props`）。
- 降级回滚：`Install-SSSNanaZipPackage.ps1 -ForceUpdate`（ForceUpdateFromAnyVersion 允许降版本，设置保留在 LocalState）。
- exe 安装器不需要升版（无此约束）。

## 六、exe 安装器与 Win11 右键菜单

- 安装器：`build\安装器\NanaZipSetup.iss`（Inno Setup 6，用户级安装免管理员/UAC，含 FM + 文件关联 + 命令行）。
- **Win11 默认右键菜单**（解压专家同款方案）：`build\安装器\ShellExt\` 壳包（MSIX 注册壳，`Add-AppxPackage -ExternalLocation` 部署，注册官方 CLSID `CAE3F1D4-7765-4D98-A060-52CD14D56EAB` 的 comServer + fileExplorerContextMenus）。
  - 安装器用 `[Code]` 事件钩子（`ssPostInstall`）执行注册——**静默/升级模式不执行 `[Run]` 段**（踩过）。
  - `NanaZip.ShellExtension.dll` 无 `DllRegisterServer`，regsvr32 注册不了；壳包是唯一路径。
  - 壳包 manifest 模板 `AppxManifest.xml` 的 Version 是 `{VERSION}` 占位，`03-组装文件集.ps1` 按版本替换后用 makeappx `/nv` 打包 + 开发证书签名。
- 卸载自动 `Remove-AppxPackage`（`[Code]` usUninstall 钩子）。

## 七、.local 目录的角色（可删，克隆后重建）

`.local\` 全部被 .gitignore 忽略，不进 git，随时可删：

- `pkg91\x64`：日常验证解包目录（替换模式的目标）。
- `pkg90\x64`：布局对照基准（官方/上一版本解包）。
- `SSSDevSigning\SSS-NanaZip-Development.cer`：开发证书公钥（私钥在证书库 `Cert:\CurrentUser\My`，store-only，脚本自动从库中取）。
- `*.md`：开发过程文档/踩坑记录（本地笔记，不进 git）。

克隆仓库后重建流程：

1. `build\SSSDevSigning\Build-SSSNanaZipPackage.ps1 -SignAllMsix` 全量构建并安装（或先装旧包解包出 pkg90/pkg91）。
2. 日常迭代用 `build\构建发布.ps1 -Mode 替换`；打安装包用 `-Mode 构建`。
3. 证书重建（如本机证书被清）：`build\SSSDevSigning\New-SSSDevCertificate.ps1 -StoreOnly` → `Install-SSSDevCertificate.ps1`。

## 八、硬性注意事项（每条都是踩过的坑）

### 1. 编码
- .cpp/.h 含中文必须是 **UTF-8 带 BOM**（项目 /WX，无 BOM 按 GBK 读 → C4819 报错）。
- **.rc 文件是 UTF-16 LE + BOM**（与 .cpp 不同）：双重 BOM / 反序行尾（0A0D）/ 末尾无换行 → RC1004。
- **.ps1 脚本含中文必须是 UTF-8 带 BOM**（PowerShell 5.1 无 BOM 按 ANSI 读 → 语法错乱）。

### 2. XAML 栈（UWP，不是 WinUI 3）
- NanaZip.Modern 用 `winrt::Windows::UI::Xaml`（Mile.Xaml 2.5.1616 承载）。
- ComboBox 无 `TextChanged`（用 LostFocus / SelectionChanged）；Border 无 `IsEnabled`（Border 不是 Control）。
- 事件处理器参数 `UNREFERENCED_PARAMETER(sender)` 和 `UNREFERENCED_PARAMETER(e)` 都要写（C4100 也是错误）。
- XAML 页面四件套：`.xaml/.cpp/.h/.idl`，新增后**必须加进 vcxproj**（NanaZip.Modern.vcxproj；页面 winmd 在 `Output\Objects\...\Unmerged\` 出现即说明已纳入）。

### 3. 共享头 ABI（NanaZip.Modern.h）
- 跨 DLL 结构体（`K7_*_DIALOG_CONTEXT`）与 `K7ModernShow*` 导出声明都在此头。
- **导出声明必须放在结构体 typedef 之后**（否则 C2061/C2733）。
- 改此头 → 依赖图内所有项目全量重编（FM 单入口天然覆盖）。
- 页面 .cpp 用了某个 Page 类型，NanaZip.Modern.cpp 里要 `#include "XxxPage.h"`（漏了报 C2039）。

### 4. 常见编译错误模式
- `IReference<bool>`：设 CheckBox 用页面内的 `BoxBool(bool)` 辅助函数，不要直接用 `winrt::box_value`（C2248）。
- BOOLEAN vs bool 比较（C4805）：`(Context->Flag != FALSE) != boolVar`。
- `std::max` 混 LONG/int（C2672）：统一类型。
- **声明晚于使用（C2065）**：常量/静态变量定义在使用之后（尤其跨匿名 namespace 与具名 namespace），上移到使用之前。
- LTCG 提示 `Previous IPDB and IOBJ mismatch` = 编译器开关/入口变化，会全量重编（正常）；固定同一入口连续编译才缓存命中。
- **FM 单入口不编译 `NanaZip.Password.cpp`**（属 ShellExtension / Universal.Windows 链）；只改它要用 `-Mode 构建` 验证。

### 5. Mile.Project.Configurations SDK 包机制
- 项目 import 的 SDK 只处理内建认识的 Mile 包；**Mile.Mobility 不被处理**，需要手动 IncludePath（已加在 NanaZip.Modern.vcxproj，别删）。

### 6. 7zG 命令行调试（看弹窗）
- 7zG = `NanaZip.Universal.Windows.exe`（命令驱动：无参数显示 "Specify command"，它不是文件管理器；双击打开用 FM `NanaZip.Modern.FileManager.exe`）。
- 压缩弹窗：`NanaZip.Universal.Windows.exe a -ad test.7z test.txt`；解压弹窗：`... x -ad test.7z -oout`。
- `-ad` = 显示对话框开关；`-ssdlg` 已被定制改语义，别用错。
- 失败排查：诊断日志 `%TEMP%\k7compress_diag.log`。
- 路径含中文会被 Start-Process 传坏，测试用英文路径。

### 7. 文件占用
- NanaZip 进程锁 DLL（杀进程 + 等 2s 重试）。
- `resources.pri` 可能被内存映射锁（"用户映射区域"错误）。
- explorer 加载 shell 扩展可锁 K7Base/K7User/Modern/FM（杀 NanaZip 不够，重试等待释放）。

### 8. 深色/系统对话框
- 弹系统对话框（IFileDialog 等）期间用 `K7UserDarkModeWorkaroundBypassScope`（K7User.dll 导出，RAII）临时禁用深色劫持。

### 9. Win11 右键菜单
- 静态注册表 verb（HKCU\Software\Classes\*\shell）**不进 Win11 默认菜单**（被折叠到"显示更多选项"）。
- 默认菜单直接显示必须走 `fileExplorerContextMenus`（packaged COM），即第六节的壳包方案。
