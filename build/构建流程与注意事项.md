# NanaZip 定制版 · 构建流程与注意事项

> 供其他会话/模型参考。仓库位置：`E:\NanaZip`（git 工作区）。
> 本文件随仓库管理（`build\` 进 git），克隆后即可按此构建。
> `.local\` 被 .gitignore 忽略（解包运行目录/本地产物，不进 git，可随时删）。
> 包身份：`SSS.NanaZip.RemotePassword`，Publisher `CN=SSS NanaZip Development`，证书工具链见 `build\SSSDevSigning\README.md`。
> 当前迭代基线：包版本 6.5.1823.0。

## 一、三条路径总览

| 路径 | 用途 | 入口 |
|---|---|---|
| **日常 UI 迭代** | 改代码 → 增量编译替换 → 在 pkg91 解包目录验证（不打包不安装） | `build\更新pkg91.ps1` |
| **增量打包** | 增量编译 → x64 单平台 msix → 签名（可安装验证，~3 分钟） | `build\打包x64.ps1` |
| **发布/全量构建** | 清空 Output 全量构建（Debug+Release x64）→ bundle → 签名 → 安装（~21 分钟） | `build\SSSDevSigning\Build-SSSNanaZipPackage.ps1 -SignAllMsix` |

日常迭代走第一条（秒级到分钟级）；要装包验证最新功能走第二条；干净发布走第三条。

## 二、日常迭代：一键脚本

```powershell
& 'E:\NanaZip\build\更新pkg91.ps1'           # 编译 + 刷新 resources.pri + 替换 + 核对
& 'E:\NanaZip\build\更新pkg91.ps1' -SkipPri  # 跳过 resources.pri（只改 .cpp/.h 时用）
```

脚本内部按顺序做 5 件事：

1. **杀 NanaZip 进程**（解锁 DLL 占用）。
2. **单入口编译**（见下"编译命令"），依赖图自动展开，一次覆盖包内全部项目。
3. **默认刷新 resources.pri**：`wapproj` x64 单平台打包（`-p:AppxBundlePlatforms=x64 -p:AppxBundle=Never`；PriGen 增量，XAML 未变时可能不重写文件）。
4. **18 文件白名单替换**到 `pkg91\x64`（按时间戳对比，源取 `Output\Binaries\Release\x64` 与 `...\NanaZipPackage\x64` 中最新者；缺失文件从 `pkg90\x64` 补齐；pkg90 缺失时自动跳过核对）。
5. **布局核对**：pkg91\x64 与 pkg90\x64 文件列表对比（多余/缺失）。

可参数化：`-Pkg91 <目录>` / `-Pkg90 <目录>`（默认 `<仓库根>\.local\pkg91|pkg90`）。

### 编译命令（脚本第 2 步，也是手动编译的唯一正确入口）

```
cmd /c "call "C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat" >nul 2>&1 && msbuild NanaZip.UI.Modern\NanaZip.Modern.FileManager.vcxproj /p:Configuration=Release /p:Platform=x64 /m /v:minimal /nologo"
```

要点（每条都实测过）：
- **只编 `NanaZip.Modern.FileManager.vcxproj` 一个项目**。vcxproj 层通过 props 全局注入依赖，MSBuild 自动展开整个依赖图（K7Base / K7User / Codecs / Core / Modern / ShellExtension / Universal.Windows + 各 Sfx），一次编全，不用按改动范围选项目。实测比"11 项目循环"快 5 倍（264s → 48s）。唯一例外：`Universal.Console` 不在 FM 依赖链上，改它才需单独编（UI 迭代用不到）。
- **vcvars64.bat**（原生 x64 环境），不要用 vcvarsall x86。
- **/m** 全核并行，**/v:minimal /nologo** 精简输出。
- 不要用 slnx / wapproj 做"只编译"：slnx 会打包+编 ARM64，wapproj 的 Build 把编译与打包焊死。
- 产物：`E:\NanaZip\Output\Binaries\Release\x64\`。

### resources.pri 判断规则（脚本第 3 步是否要跑）

| 改动类型 | 是否需要刷新 pri |
|---|---|
| `*.xaml` / `App.xaml` / `*.resw` / Manifest | **需要**（跑不带 `-SkipPri`） |
| 只改 `*.cpp` / `*.h`（纯逻辑） | **不需要**（加 `-SkipPri`） |

判断依据：pkg91\x64 里 `resources.pri` 的时间戳 vs 源文件时间戳，XAML 比 pri 新就需要刷。

## 三、增量打包（验证最新功能的安装包）

```powershell
& 'E:\NanaZip\build\打包x64.ps1'
```

- 增量编译（未改动文件 MSBuild 自动跳过）→ wapproj x64 单平台 msix → 自动签名。
- 产物：`Output\Binaries\AppPackages\NanaZipPackage_<ver>_x64_Test\*.msix`。
- 安装（覆盖更新，不卸载原包）：

```powershell
& 'E:\NanaZip\build\SSSDevSigning\Install-SSSNanaZipPackage.ps1' `
  -PackagePath 'E:\NanaZip\Output\Binaries\AppPackages\NanaZipPackage_<ver>_x64_Test\NanaZipPackage_<ver>_x64.msix' `
  -ForceUpdate
```

- 版本号由构建任务按 git 提交日期自动递增（`NanaZip.Project\NanaZip.Project.Version.props` / `NanaZipPackage\Package.appxmanifest` 会被 RefreshVersion 改写，随构建提交）。
- 同版本覆盖或降级回滚才需要 `-ForceUpdate`；正常升版本不带也能装。
- 首次在全新 Output 上跑会接近全量（`Previous IPDB and IOBJ mismatch` 属正常）；连续增量时缓存命中，编译秒过。

## 四、发布/全量构建（仅发布/干净验证用）

```powershell
cd E:\NanaZip
# 完整构建 + 签名所有产物（清空 Output；Debug + Release x64 + bundle；~21 分钟）
& 'E:\NanaZip\build\SSSDevSigning\Build-SSSNanaZipPackage.ps1' -SignAllMsix

# 只对现有产物签名（跳过构建）
& 'E:\NanaZip\build\SSSDevSigning\Build-SSSNanaZipPackage.ps1' -SkipBuild -SignAllMsix

# 安装（覆盖更新，不卸载原包）
& 'E:\NanaZip\build\SSSDevSigning\Install-SSSNanaZipPackage.ps1' `
  -PackagePath '<产物路径>\*.msixbundle' -ForceUpdate

# 验证
Get-AppxPackage -Name 'SSS.NanaZip.RemotePassword'
```

- 证书/签名/安装的完整说明：`build\SSSDevSigning\README.md`（store-only 私钥在 `Cert:\CurrentUser\My`，公钥 `.cer` 在 `.local\SSSDevSigning\`）。
- 包占用 0x80073D02：先 `Remove-AppxPackage` 再装。
- explorer 锁 shell 扩展必要时重启 explorer。

## 五、.local 目录的角色（可删，克隆后重建）

`.local\` 全部被 .gitignore 忽略，不进 git，随时可删：

- `pkg91\x64`：日常验证解包目录（更新pkg91.ps1 的替换目标）。
- `pkg90\x64`：布局对照基准（官方/上一版本解包）。
- `SSSDevSigning\SSS-NanaZip-Development.cer`：开发证书公钥（私钥在证书库，脚本能自动从库中取）。

克隆仓库后重建流程：

1. `build\SSSDevSigning\Build-SSSNanaZipPackage.ps1 -SignAllMsix` 全量构建并安装（或先装旧包解包出 pkg90/pkg91）。
2. 日常迭代就用 `build\更新pkg91.ps1`；打安装包用 `build\打包x64.ps1`。
3. 证书重新创建（如本机证书被清）：`build\SSSDevSigning\New-SSSDevCertificate.ps1 -StoreOnly` → `Install-SSSDevCertificate.ps1`。

## 六、硬性注意事项（每条都是踩过的坑）

### 1. 编码
- .cpp/.h 含中文必须是 **UTF-8 带 BOM**（项目 /WX，无 BOM 按 GBK 读 → C4819 报错）。文本编辑器保存为 UTF-8 无 BOM 时编译器按 936 解析中文会直接 C4819 warning-as-error。
- **.rc 文件是 UTF-16 LE + BOM**（注意与 .cpp 不同）：双重 BOM / 反序行尾（0A0D）/ 末尾无换行 → RC1004。编辑工具改完 rc 用字节级检查。

### 2. XAML 栈（UWP，不是 WinUI 3）
- NanaZip.Modern 用 `winrt::Windows::UI::Xaml`（Mile.Xaml 2.5.1616 承载）。
- ComboBox 无 `TextChanged`（用 LostFocus / SelectionChanged）；Border 无 `IsEnabled`（Border 不是 Control）。
- 事件处理器参数 `UNREFERENCED_PARAMETER(sender)` 和 `UNREFERENCED_PARAMETER(e)` 都要写（C4100 也是错误）。
- XAML 页面四件套：`.xaml/.cpp/.h/.idl`，新增后**必须加进 vcxproj**（NanaZip.Modern.vcxproj；页面 winmd 在 `Output\Objects\...\Unmerged\` 出现即说明已纳入）。

### 3. 共享头 ABI（NanaZip.Modern.h）
- 跨 DLL 结构体（`K7_*_DIALOG_CONTEXT`）与 `K7ModernShow*` 导出声明都在此头。
- **导出声明必须放在结构体 typedef 之后**（先定义 `K7_*_DIALOG_CONTEXT` 再声明函数，否则 C2061/C2733）。
- 改此头 → 依赖图内所有项目全量重编（FM 单入口天然覆盖，不用手动挑项目）。
- 页面 .cpp 用了某个 Page 类型，NanaZip.Modern.cpp 里要 `#include "XxxPage.h"`（漏了报 C2039）。

### 4. 常见编译错误模式
- `IReference<bool>`：设 CheckBox 用页面内的 `BoxBool(bool)` 辅助函数，不要直接用 `winrt::box_value`（C2248）。
- BOOLEAN vs bool 比较（C4805）：`(Context->Flag != FALSE) != boolVar`。
- `std::max` 混 LONG/int（C2672）：统一类型。
- **声明晚于使用（C2065）**：常量/静态变量若定义在使用函数之后（尤其跨匿名 namespace 与具名 namespace），编译不过；把常量上移到使用之前。
- LTCG 提示 `Previous IPDB and IOBJ mismatch` = 编译器开关/入口变化，会全量重编（正常）；固定同一入口连续编译才缓存命中（`0 of N functions`）。
- **FM 单入口不编译 `NanaZip.Password.cpp`**（属于 ShellExtension / Universal.Windows 链）；只改它要用 `打包x64.ps1` 或全量构建验证。

### 5. Mile.Project.Configurations SDK 包机制
- 项目 import 的 SDK 只处理内建认识的 Mile 包；**Mile.Mobility 不被处理**，需要手动 IncludePath（`$(UserProfile)\.nuget\packages\mile.mobility\1.1.602\Source\Native\`，已加在 NanaZip.Modern.vcxproj，别删）。

### 6. 7zG 命令行调试（看弹窗）
- 7zG = `NanaZip.Universal.Windows.exe`，直接跑解包目录版本（`pkg91\x64` 自带 pri，XAML 能起）：
  - 压缩弹窗：`NanaZip.Universal.Windows.exe a -ad test.7z test.txt`
  - 解压弹窗：`NanaZip.Universal.Windows.exe x -ad test.7z -oout`
- `-ad` = 显示对话框开关（压缩/解压都要带）；`-ssdlg` 已被定制改语义（对话框状态文件），别用错。
- 验证：进程活着 + MainWindowHandle 非 0 + 标题对；首次 XAML 初始化可能慢几秒（短暂无响应属正常）。
- 失败排查：诊断日志 `%TEMP%\k7compress_diag.log`（U1-U5 / M1-M6 / P10 等编号），日志停在哪就是失败点。
- 路径含中文会被 Start-Process 传坏，测试用英文路径。

### 7. 文件占用
- NanaZip 进程锁 DLL（杀进程 + 等 2s 重试）。
- `resources.pri` 可能被内存映射锁（"用户映射区域"错误）。
- explorer 加载 shell 扩展可锁 K7Base/K7User/Modern/FM（杀 NanaZip 不够，重试等待释放）。

### 8. 深色/系统对话框
- 弹系统对话框（IFileDialog 等）期间用 `K7UserDarkModeWorkaroundBypassScope`（K7User.dll 导出，RAII）临时禁用深色劫持，弹完自动恢复。
